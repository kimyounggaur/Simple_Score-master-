## 1. 한 줄 요약과 비전

**Harmony는 "3초 안에 작곡을 시작할 수 있고, 학생도 작곡가도 똑같이 행복한" 웹 기반 악보 편집기입니다.**

기존 악보 프로그램들은 두 부류로 나뉩니다.

- **전문가용** (Dorico, Sibelius, Finale) — 강력하지만 학습곡선이 가파르고, 데스크톱·유료·무거움
- **교육·협업용** (Flat.io, Noteflight, Soundslice) — 가볍지만 음악적으로 빈약하거나 기능이 분산되어 있음

Harmony는 그 사이에서 **"전문가의 깊이 + 학습자의 친근함 + 웹의 즉시성"** 을 동시에 노립니다. 핵심은 *"기능을 쌓아 올리는 것"이 아니라 "마찰을 제거하는 것"* 입니다.

> ❝ 좋은 악보 프로그램은 작곡가의 머릿속을 그대로 종이로 옮긴다. 위대한 악보 프로그램은 옮기는 동안 작곡가가 멈춰 생각하게 만들지 않는다. ❞

## 2. 왜 지금인가 — 시장 진단

### 2.1 시장 신호

| 신호 | 의미 |
|---|---|
| **Finale 단종 (2024)** | 전문 사용자 수십만 명이 대안을 찾는 중 — MuseScore·Dorico로 이주 가속 |
| **PreSonus Notion 단종 흐름** | 모바일·터치 시장의 빈자리 |
| **MuseScore 4의 약진** | 무료 + 고품질 사운드. 진입장벽 급격히 낮아짐 |
| **AI·음성·필기 입력의 일반화** | 노트 입력 패러다임 자체가 바뀌는 중 |
| **웹 기술의 성숙** | WebMIDI, WebAudio, WebAssembly, WebGPU로 데스크톱급 성능이 브라우저에서 가능 |

### 2.2 사용자의 진짜 불만

각 커뮤니티 리뷰·포럼을 정성 분석한 결과, 사용자들이 공통으로 호소하는 페인 포인트는 다음과 같습니다.

1. **"열기까지 너무 오래 걸린다"** — 데스크톱 프로그램의 무거움
2. **"단축키를 다 외워야 빠르다"** — 학습곡선
3. **"모바일에서 그냥 보고 싶을 뿐인데 안 된다"** — 멀티 디바이스 단절
4. **"학생에게 보내려면 PDF 변환 → 메일 → 인쇄 — 3단계"** — 공유 마찰
5. **"음향이 가짜 같다"** — 재생 품질
6. **"악보가 자동으로 예쁘게 나오지 않는다"** — 인그레이빙 부담
7. **"협업이 안 되거나, 되더라도 실시간이 아니다"** — Sibelius·Finale·Dorico 모두 약점

→ 이 7가지를 **모두 해결한 제품은 아직 없습니다.** Harmony의 기회입니다.

## 3. 경쟁 프로그램 강점·약점 분석

각 프로그램에서 **반드시 가져와야 할 DNA**를 정리했습니다.

### 3.1 Dorico (Steinberg)

**🟢 가져올 것**
- **Popover 시스템**: `Shift+C` 음자리표, `Shift+K` 조표, `Shift+M` 박자, `Shift+D` 셈여림, `Shift+T` 빠르기… → "메뉴를 헤매지 않고 키보드로 모든 것을 입력"
- **Insert 모드**: 음을 추가·삭제해도 뒤의 음악이 밀려나거나 덮어쓰지 않음 (비파괴 편집)
- **5개 모드 분리**: Setup / Write / Engrave / Play / Print — 단계별 인지 부하 분산
- **Jump Bar (`J` 키)**: Spotlight식 명령 팔레트 — "원하는 걸 타이핑하면 즉시 실행"
- **자동 보표 정리**: 사용자가 layout을 만지지 않아도 깔끔하게
- **Transform 도구**: `rot2`, `inv`, `ret`, `c maj to e maj` 같은 텍스트 명령
- **Flow 개념**: 한 파일 안에 여러 악장·곡을 독립적으로 관리

**🔴 피할 것**
- 데스크톱 전용, 유료 라이선스, 학습곡선 매우 가파름
- "마우스로 음표를 끌어옮기는 직관적 동작"이 뒤늦게야 추가됨

### 3.2 Sibelius (Avid)

**🟢 가져올 것**
- **Magnetic Layout**: 요소가 서로 자동으로 충돌을 피해 배치
- **친숙한 메뉴 구조**: 음악교사 세대에 익숙한 워크플로우
- **MIDI 실시간 입력 인식**: 연주를 그대로 받아 적기

**🔴 피할 것**
- 클라우드 협업이 어색하고 느림
- UI가 시대에 비해 무거움

### 3.3 MuseScore 4

**🟢 가져올 것**
- **무료 + 오픈소스 정신**: 진입장벽 0
- **MuseSounds**: 무료치고 매우 사실적인 오케스트라·악기 사운드
- **MusicXML 완벽 지원**: 상호 운용성
- **거대한 공유 라이브러리**: musescore.com에 수백만 악보
- **플러그인 생태계**

**🔴 피할 것**
- 협업·클라우드 워크플로우 빈약
- 모바일 경험 단순 뷰어 수준
- 인그레이빙 품질이 Dorico/Finale에 비해 한 단계 아래

### 3.4 Flat.io

**🟢 가져올 것**
- **실시간 협업** (Google Docs급) — 동시 편집, 변경 추적, 코멘트
- **웹 + iOS + Android 완전 동기화** — 노트북에서 시작해 폰에서 수정
- **Google Classroom·Docs 임베드** — 교육 현장 통합
- **깨끗하고 가벼운 UI** — "처음 본 사람도 5분 안에 첫 곡"
- **오프라인 모드 + 자동 동기화**

**🔴 피할 것**
- 인그레이빙·고급 기보 한계
- 전문가용 기능 부재

### 3.5 Noteflight

**🟢 가져올 것**
- **85,000+ 악보 라이브러리** (Hal Leonard 제휴)
- **Marketplace**: 자신의 편곡을 판매 가능
- **Google Classroom 직접 연동**

**🔴 피할 것**
- 인터페이스 노후화
- 무료판 10곡 제한이 너무 박함

### 3.6 Soundslice

**🟢 가져올 것**
- **악보 ↔ YouTube/MP3 동기화** — "악보의 그 음표가 영상의 이 순간"
- **연습 도구**: 구간 반복, 속도 조절 (피치 유지), 파트 솔로
- **터치 최적화 편집기**
- **인터랙티브 학습 경험** — 클릭하면 그 위치부터 재생
- **Guitar Pro·MusicXML 임포트**

**🔴 피할 것**
- 본격적인 작·편곡 도구는 아님 (학습 중심)

### 3.7 StaffPad

**🟢 가져올 것**
- **Apple Pencil 손글씨 인식** — 종이에 쓰듯이 작곡
- **모바일 우선 UX**
- **Spitfire Audio 음원** — 영화음악급 사실성

**🔴 피할 것**
- 윈도우/iPad 전용, 웹 없음

### 3.8 Lilypond

**🟢 가져올 것**
- **텍스트 기반 → Git 버전 관리 가능**
- **인그레이빙 미학의 정점** — 클래식 출판 수준
- **프로그래밍 가능**

**🔴 피할 것**
- 일반 사용자에게 진입 불가
- 실시간 미리보기 어색

### 3.9 핵심 라이브러리 (인프라)

| 라이브러리 | 역할 | 상태 |
|---|---|---|
| **VexFlow 5** | 악보 SVG/Canvas 렌더링 | 활발, TypeScript, MIT |
| **OpenSheetMusicDisplay (OSMD)** | MusicXML → VexFlow 렌더링 | 활발, Phonicscore가 유지 |
| **alphaTab** | 기타 탭 + 표준 기보 렌더링 | 활발 |
| **Tone.js** | 웹 오디오 합성·시퀀싱 | 사실상 표준 |
| **Magenta.js / Music21** | AI 작곡 보조 | 연구·실험 단계 |

→ **렌더링은 자체 개발이 아닌 VexFlow 기반으로 시작.** 자체 인그레이빙 엔진은 v2 이후의 야망.

## 4. Harmony의 핵심 디자인 철학 5가지

설계 결정의 기준이 되는 5개 원칙입니다. 이후 모든 기능은 이 5개로 검증합니다.

### 원칙 ① **"3초 안에 시작"**
가입·로그인 없이도 첫 음표를 입력할 수 있어야 한다. 무겁고 화려한 시작 화면 대신 *빈 보표 한 줄*이 첫 화면이다. (Notion·Figma의 "Start with a blank page" 철학)

### 원칙 ② **"하나의 동작에는 세 가지 길"**
모든 입력은 **마우스·키보드·터치(또는 음성)** 세 가지 방법으로 가능해야 한다. 사용자가 자신에게 맞는 방식을 선택한다. 단축키를 외우지 않아도 모든 기능을 쓸 수 있어야 한다.

### 원칙 ③ **"기능은 숨기되, 부르면 즉시 온다"**
Dorico의 Jump Bar처럼 **Cmd+K (또는 `J`)** 로 모든 기능을 호출 가능. 평상시 화면은 깨끗하게 비워둔다. 메뉴 아이콘 30개를 늘어놓는 대신, 자주 쓰는 5개만 보이고 나머지는 호출형.

### 원칙 ④ **"가르치는 모드와 쓰는 모드는 다르다"**
**Learner Mode**(학생): 큰 음표, 색상 코드, 힌트 풍선, 실수 자동 보정
**Composer Mode**(작곡가): 미니멀, 키보드 중심, 모든 단축키 활성
**Teacher Mode**(교사): 워크시트 만들기·과제 배포·진도 확인
→ 한 앱 안에서 모드만 토글, 기능과 UI가 동시에 변형.

### 원칙 ⑤ **"악보는 들려야 한다"**
처음부터 *오디오 동기화·재생*을 1급 시민으로. Soundslice식의 "악보 ↔ 실연주 영상" 연결이 기본 옵션. 작·편곡 도구이면서 동시에 *연습 도구*.

## 5. 핵심 기능 명세

### 5.1 입력 (Input)

| 입력 방식 | 설명 | 구현 우선순위 |
|---|---|---|
| **컴퓨터 키보드 (Dorico식)** | `A-G` 음 이름, `1-9` 길이, `Shift+letter` 팝오버 | P0 |
| **MIDI 키보드 실시간** | WebMIDI API로 USB MIDI 연결, 스텝 입력 + 리얼타임 녹음 | P0 |
| **마우스 클릭·드래그** | 음표 팔레트에서 클릭 후 보표 클릭, 드래그로 음높이 조정 | P0 |
| **터치·Apple Pencil** | iPad·태블릿에서 음표 그리기, 제스처로 슬러·다이내믹 | P1 |
| **손글씨 인식** | 종이에 쓰듯이 → OCR-style ML 모델 (CRNN 기반) | P2 |
| **음성 명령** | "G장조로 바꿔줘", "4마디 추가" — Whisper + LLM | P2 |
| **자연어 작곡 명령** | "여기에 IV 화음 넣어줘", "이 멜로디를 단조로" — Claude API | P2 |
| **오디오 → 악보 변환** | 노래·연주 녹음을 MIDI로, 다시 악보로 (Spotify Basic Pitch 기반) | P3 |
| **카메라로 종이 악보 스캔** | OMR (Audiveris·SmartScore 기술 응용) | P3 |
| **MusicXML/MIDI/MXL 임포트** | 드래그 앤 드롭 | P0 |
| **손동작 (MediaPipe)** | 카메라 손 추적으로 비접촉 입력 — 실험 기능 | P3 |

### 5.2 편집 (Edit)

- **Insert Mode** (Dorico 차용): 비파괴 리듬 편집
- **Magnetic Layout** (Sibelius 차용): 요소 자동 충돌 회피
- **Transform 도구**: 전위(inversion), 역행(retrograde), 회전(rotation), 조옮김, 모달 변환
- **Smart Voicing**: 화음 분배 자동 (오케스트레이션 보조)
- **다중 선택 일괄 편집**: 선택한 음 전체에 다이내믹/아티큘레이션 동시 적용
- **무한 Undo/Redo + 시간축 스크럽**: Figma 같은 timeline scrubbing

### 5.3 인그레이빙 (Engrave)

- 기본은 **자동**, 필요할 때만 **수동 미세조정**
- 음악 폰트: SMuFL 표준 (Bravura 기본, 사용자 선택 가능)
- 페이지 레이아웃: A4/A5/Letter/모바일 가로/세로
- Engrave Mode 진입 시: 마우스로 모든 요소 픽셀 단위 이동, 보표 간격, 시스템 분할 수동 제어

### 5.4 재생·사운드 (Playback)

- **Tone.js 합성기** + **샘플 라이브러리** (CC-라이선스 + 자체 녹음)
- 90+ 악기 (관·현·타·국악기)
- 마이크 입력 가능 (보컬 트랙 녹음·동기화)
- **소리 미세 조정**: 셈여림·아티큘레이션이 재생에 실제 반영
- **외부 오디오/영상 동기화** (Soundslice식)
  - YouTube URL 붙여넣기 → 마디 매핑 → 클릭하면 영상의 그 지점 재생
  - 구간 반복(A-B loop), 속도 조절(±50%, 피치 유지), 파트 솔로/뮤트

### 5.5 협업 (Collaboration)

- **실시간 동시 편집** (CRDT 기반, Yjs 활용)
- **커서·선택 영역 색상별 표시** (Figma식)
- **마디 단위 코멘트** (Google Docs식)
- **버전 히스토리** (모든 변경 시점 복구 가능)
- **권한 관리**: 보기만 / 코멘트 / 편집 / 관리자
- **공유 링크 한 줄** — 가입 없이 보기 가능
- **임베드 코드** — 블로그·웹사이트에 인터랙티브 악보로 삽입

### 5.6 라이브러리·커뮤니티

### 7.3 데이터 모델 핵심

내부 데이터 표현은 **MusicXML과 100% 무손실 변환 가능한 JSON**으로 정의합니다.

```typescript
type Score = {
  id: string
  metadata: { title, composer, lyricist, tempo, ... }
  parts: Part[]              // 악기 파트
  flows: Flow[]              // Dorico식 곡 단위
  layout: LayoutConfig
  collaborators: User[]
  versionHistory: Version[]
}

type Part = {
  id: string
  instrument: Instrument
  staves: Staff[]            // 1~2개 (피아노=2)
}

type Measure = {
  number: number
  timeSignature?: TimeSig
  keySignature?: KeySig
  notes: Note[]
  markings: Marking[]        // 다이내믹, 페달, 슬러 등
}

type Note = {
  id: string                 // CRDT 동기화용 안정 ID
  pitch: Pitch | 'rest'
  duration: Duration         // 길이 + 점음표
  voice: number              // 다성 처리
  attachments: Attachment[]  // 아티큘레이션, 가사, 핑거링
}
```

설계 의도:
- **모든 객체에 안정 ID** → CRDT 동기화의 기반
- **렌더링과 데이터 분리** → 같은 데이터로 표준 기보·정간보·탭·피아노롤 동시 표현 가능
- **불변(immutable) 데이터** → 무한 Undo/Redo, 버전 분기

### 8.2 모드별 UI 변형

### 8.3 인터랙션 디자인 원칙

- **Optimistic UI**: 모든 동작이 즉시 반영, 서버 응답을 기다리지 않음
- **Undo는 신성하다**: 어떤 동작이든 Cmd+Z로 되돌릴 수 있어야 함
- **에러는 친절하게**: "오류 발생" 대신 "이 음은 이 악기 음역 밖이에요. 한 옥타브 아래로 옮길까요?"
- **로딩은 보여주지 않는다**: 스켈레톤 + 점진적 렌더링
- **빈 상태(empty state)는 가르친다**: 첫 화면이 튜토리얼

### 8.4 접근성 (Accessibility)

- **고대비 모드, 글자 크기 조절** — 시각 약자 대응
- **스크린 리더 친화적 SVG** — `<title>`, `<desc>` 자동 삽입
- **키보드 only 완전 조작 가능**
- **색맹 안전 색 팔레트** (적록·청황 대응)
- **다국어**: 한국어·영어 우선, 일본어·중국어·스페인어 확장

### 8.5 시각 디자인 방향

- **컬러**: 잉크 블랙 + 따뜻한 아이보리 배경 + 강조 1색 (제안: 클래식 진청 #1B2A4E 또는 한지 적색 #B83227)
- **타이포**: 본문 *Pretendard* (한글), 디스플레이 *Fraunces* 또는 *Cormorant* (영문), 음악 폰트 *Bravura*
- **분위기**: 종이·잉크의 물성을 디지털로 — Notion이나 iA Writer의 절제된 미감
- **모션**: 절제된 페이드, 0.2초 내외, 의미 있는 전환만
