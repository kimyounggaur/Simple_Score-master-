# 차세대 웹 기반 악보 플랫폼 개발 계획서 (Development Blueprint)

본 문서는 모든 기존 악보 프로그램들의 장점을 집약하여, 가장 직관적이고 사용자 친화적인 차세대 웹 기반 악보 편집 및 교육 플랫폼(가칭: **OpusWeb / Simple Score Ecosystem**)을 구축하기 위한 심층 개발 계획서입니다.

---

## 1. 프로젝트 비전 및 핵심 철학

### 1.1 비전 (Vision)
> **"사용자는 오직 음악에만 집중한다. 악보를 예쁘게 조판하고 배치하는 것은 기술이 알아서 한다."**

기존의 데스크톱 악보 프로그램(Finale, Sibelius)의 강력한 기능과 웹 기반 협업 툴(Flat.io)의 뛰어난 접근성을 결합하여, 유치원생부터 전문 연주자, 그리고 다양한 악기를 다루는 강사들까지 누구나 학습 곡선 없이 즉시 사용할 수 있는 에듀테크(EdTech) 혁신 플랫폼을 지향합니다.

### 1.2 핵심 설계 원칙 (Core Principles)
1. **점진적 공개 (Progressive Disclosure):** 복잡한 기능은 숨기고, 사용자가 필요로 하는 순간에만 적절한 메뉴를 노출하여 인지 부하를 최소화합니다.
2. **악기별 커스텀 콘텍스트:** 타악기, 현악기, 관악기 등 각 악기의 특성에 맞는 전용 주법 및 기호 입력 시스템을 자동으로 제공합니다.
3. **타협 없는 고성능:** 웹 브라우저 환경에서도 오케스트라 총보를 실시간으로 렌더링하고 편집할 수 있는 강력한 엔진을 구축합니다.

## 2. 벤치마킹 및 차별화 전략

기존 시장의 대표적인 프로그램들의 장단점을 철저히 분석하여, 장점은 흡수하고 단점은 혁신적으로 해결합니다.

| 비교 대상 | 흡수할 장점 (도입 목표) | 극복할 단점 (해결 방안) |
| :--- | :--- | :--- |
| **Dorico** | 완벽한 자동 레이아웃 및 객체 간 충돌 방지 알고리즘 | 수직에 가까운 단축키 학습 곡선 <br>→ **노션 스타일의 콘텍스트 메뉴**로 해결 |
| **Flat.io** | 설치가 필요 없는 웹 접근성, 실시간 동시 협업 환경 | 부족한 조판(Engraving) 디테일 및 대용량 렉 <br>→ **WebAssembly(WASM) 고속 엔진** 도입 |
| **Soundslice** | 실제 미디어(오디오/유튜브)와 악보의 완벽한 동기화 | 감상 및 학습 위주의 한계 <br>→ **강력한 작곡/편집 및 AI 채보 기능** 결합 |
| **MuseScore** | 방대한 오픈소스 악보 및 커뮤니티 생태계 | 파편화된 UI와 무거운 구동 체계 <br>→ **모듈형 단일 페이지 애플리케이션(SPA)** 적용 |

## 3. 콘텍스트 기반 UI/UX 설계 (Notion 스타일의 미니멀리즘)

화면에 수백 개의 아이콘과 메뉴를 상시 배치하는 전통적인 방식을 버리고, 극도의 깔끔함과 직관성을 유지합니다.

### 3.1 슬래시(`/`) 커맨드 및 스마트 플로팅 툴바
* **슬래시 명령어:** 빈 마디를 선택하고 `/` 키를 누르면 `[음자리표 변경]`, `[조표 변경]`, `[도돌이표 추가]` 등 마디 단위 설정 메뉴가 드롭다운으로 나타납니다.
* **스마트 플로팅 툴바:** 특정 음표를 드래그하거나 다중 선택하면, 해당 음표 위에 볼드/이탤릭 툴바처럼 `[이음줄]`, `[스타카토]`, `[셈여림 기호]` 팝업 메뉴가 마우스 포인터 근처에 즉시 나타납니다.

### 3.2 악기 특성별 인스펙터(Inspector) 자동 전환
시스템이 악보의 트랙 특성을 감지하여 UI를 유연하게 변경합니다.
* **타악기 (젬베, 카혼, 장구 등):** 오선지 대신 단선율 또는 악기별 커스텀 라인을 제공하며, `[림샷(Rimshot)]`, `[슬랩(Slap)]`, `[플럭(Pluck)]` 등의 주법 기호를 최상단 툴바에 배치합니다.
* **현악기 (첼로, 바이올린, 기타 등):** `[보잉 기호(Up/Down)]`, `[포지션 마크]`, `[글리스앤도]` 및 타블라추어(TAB) 악보 전환 버튼을 활성화합니다.
* **관악기 (플루트, 클라리넷, 색소폰 등):** 이조 악기를 위한 `[실음/이조음 즉시 전환 버튼]`과 숨표, 아티큘레이션 중심의 메뉴를 노출합니다.

### 3.3 모바일 및 패드 최적화 (Zen Mode)
* 레슨실이나 야외 연주 환경에서 태블릿 하나로 악보를 보며 즉석 편집할 수 있도록 **핀치 줌(Pinch-Zoom)** 및 **스와이프 제스처**를 지원합니다.
* 불필요한 UI 요소를 모두 숨기고 오직 악보만 화면에 가득 채우는 **'무한 캔버스 젠 모드(Zen Mode)'**를 제공합니다.

## 4. 고성능 렌더링 엔진 기술 스택

웹에서 데스크톱 수준의 매끄럽고 정교한 조판을 처리하기 위해 현대적인 웹 기술을 유기적으로 결합합니다.

```
[클라이언트 브라우저 (React / Zustand)]
       │
       ├──(상태 조작 및 UI 가이드)──> [VexFlow + OSMD] (Canvas/SVG 렌더링)
       │                                     ▲
       └──(대용량 자동 조판 연산)───────> [WebAssembly (Rust/C++) 코어]
```

* **프론트엔드 및 상태 관리:** `React.js` 프레임워크와 경량 상태 관리 라이브러리 `Zustand`를 조합하여 UI 반응 속도를 극대화합니다.
* **렌더링 코어 (VexFlow & OSMD):**
  * HTML5 Canvas 및 SVG 기반의 강력한 오픈소스 악보 렌더링 API인 **VexFlow**를 커스텀하여 사용합니다.
  * 표준 MusicXML 파싱 및 화면 배치를 위해 **OpenSheetMusicDisplay(OSMD)** 라이브러리를 결합하여 높은 호환성을 확보합니다.
* **엔진 최적화 (WebAssembly):**
  * 수십 개 성부의 대규모 총보 레이아웃 계산, 음표 간의 충돌 방지 알고리즘 등 연산 집약적인 로직은 **Rust** 또는 **C++**로 작성한 후 **WebAssembly(WASM)**로 빌드하여 자바스크립트 대비 수십 배 빠른 성능을 보장합니다.

## 5. AI 기반 오디오 채보 파이프라인 (Audio-to-Score)

사용자가 악기 연주 녹음 파일(MP3, WAV) 또는 음원을 업로드하면 클라우드에서 정교한 악보 데이터(MusicXML)로 자동 변환하는 아키텍처입니다.

```
[오디오 파일 업로드]
       │
       ▼
[1단계: 음원 분리 (Source Separation)]
  - 기술 스택: Python, AI 모델 (Meta Demucs 또는 Deezer Spleeter)
  - 역할: 혼합된 음원에서 피아노, 드럼, 보컬, 기타 등 악기별 독립 트랙(Stem) 추출
       │
       ▼
[2단계: 피치 및 온셋 추출 (Pitch & Onset Detection)]
  - 기술 스택: Spotify Basic Pitch, Omnizart
  - 역할: 분리된 오디오 신호를 분석하여 음표의 시작 시점(Onset)과 정확한 음높이(Pitch)를 파악, 다성부(Polyphonic) MIDI 데이터 생성
       │
       ▼
[3단계: 퀀타이징 및 악보 최적화 (Quantization & MusicXML Mapping)]
  - 기술 스택: Python music21 라이브러리, 자체 그리드 보정 알고리즘
  - 역할: 인간 연주의 미세한 박자 오차를 8분음표, 16분음표 등 정제된 노트 길이로 보정(Quantization)하고 코드 진행을 유추하여 표준 MusicXML로 최종 변환
       │
       ▼
[화면 렌더링 및 스코어 클라우드 저장]
```

## 6. 단계별 개발 로드맵 (12개월 계획)

### Phase 1: 코어 엔진 구축 및 MVP 개발 (1~3개월 차)
* Canvas/SVG 기반 악보 기본 렌더링 파이프라인 완성
* 단일 성부(Solo) 음표 추가, 삭제, 수정 기능 구현
* 표준 MusicXML 데이터 구조(Schema) 설계 및 파서 구현

### Phase 2: 미니멀 UI/UX 및 파일 호환성 확보 (4~6개월 차)
* 슬래시 커맨드 및 컨텍스트 기반 플로팅 툴바 UI 구현
* 다중 성부(Multi-stave) 및 대규모 오케스트라 스코어 뷰 레이아웃 최적화
* 외부 파일(Sibelius, MuseScore에서 추출한 MusicXML, MIDI) 가져오기/내보내기 완성

### Phase 3: 실시간 협업 및 고품질 재생 엔진 (7~9개월 차)
* WebSockets 및 CRDT(Conflict-free Replicated Data Type) 기반의 다중 사용자 실시간 동시 편집 시스템 구축
* Web Audio API와 SoundFont/Web Audio Font 기술을 활용하여 악기별 실제 사운드에 가까운 고품질 재생(Playback) 플레이어 탑재

### Phase 4: AI 통합, 클라우드 생태계 및 베타 오픈 (10~12개월 차)
* Python 기반 오디오 자동 채보 파이프라인 API 연동
* 개인 강사 및 학원을 위한 '스코어 클라우드(Score Cloud)' 공유 기능 및 도큐먼트 자동화 템플릿 결합
* 클로즈드 베타 테스트 진행 후 글로벌 오픈 베타 런칭
